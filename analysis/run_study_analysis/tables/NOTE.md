# Freshness and manual refresh procedure

The publication tables in this directory are generated by `publication_tables.r`. Every CSV
they draw on must reflect the same cleaned dataset. The pipeline enforces this automatically
for three of the four hops, but one hop requires a manual step.

## The four-hop chain

```
BQ source
  --[MANUAL: export script]--> data/export/qualtrics_fct_panel_responses.csv
  --[make study_data_quality]--> data/export/qualtrics_fct_panel_responses_cleaned.csv
  --[make study_analysis]--> figs/{eda,corr,cfa,mlm}/*.csv
  --[make study_tables]--> tables/*.docx
```

## What the code enforces automatically

- `data_quality.r` checks that the raw panel CSV exists before running.
- Every analysis script (`eda.r`, `correlation.r`, `measurement_model.r`, `multilevel_model.r`)
  calls `load_cleaned_data()`, which stops loudly if the cleaned CSV is older than the raw
  panel CSV. Run `make study_data_quality` to fix.
- `publication_tables.r` stops loudly if any figs CSV is older than the cleaned CSV.
  Run `make study_analysis` to fix.

## The un-guarded hop: BigQuery to raw panel CSV

The export script reads from BigQuery (`dkg-phd-thesis.qualtrics.fct_panel_responses`). There
is no local file the script can compare timestamps against to know whether BQ has been updated
since the last export. The code cannot detect this staleness automatically.

**When must you re-export?** Any time:
- New participant responses have been added to BigQuery.
- The careless-responder exclusion criteria were changed and the fact table was rebuilt.
- You are unsure whether the local CSV reflects the current BQ state.

## Manual refresh procedure

Run from the project root. Requires gcloud ADC (`gcloud auth application-default login`).

```bash
# Step 1: Re-export from BigQuery (requires explicit confirmation; never runs autonomously)
bash analysis/run_study_analysis/scripts/export_study_fct_panel_responses_csv.sh

# Step 2: Regenerate all analyses and tables in dependency order
make study_all
```

`make study_all` runs `study_data_quality -> study_analysis -> study_tables` in order and
is the single command to use whenever you want a guaranteed-fresh set of tables.
